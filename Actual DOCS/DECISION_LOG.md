# DECISION LOG — Журнал архитектурных решений

Здесь фиксируются причины ключевых технических и дизайнерских решений.
Цель: чтобы через месяц (или год) было понятно — *почему* сделано именно так,
а не иначе, и стоит ли это менять.

Формат каждой записи:
- **Статус:** `принято` | `пересматривается` | `отменено`
- **Контекст:** что за задача, какие были варианты
- **Решение:** что выбрано
- **Причина:** почему именно это
- **Последствия:** что это накладывает на будущее

---

## ADR-001 · Ванильный HTML/CSS/JS без фреймворков

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Лендинг — одна страница. Рассматривались: Next.js, Astro, SvelteKit, просто HTML.

**Решение:** чистый HTML + CSS + JS, без npm, без сборщика.

**Причина:**
- Нет необходимости в роутинге, стейте, SSR
- Деплой = загрузить три файла куда угодно
- Нет зависимостей → нет уязвимостей, нет устаревших пакетов
- Время загрузки минимальное

**Последствия:**
- При масштабировании (блог, кабинет клиента) — потребуется переход на фреймворк
- Нет hot-reload при разработке (решается `npx serve .` или Live Server в VS Code)

## ADR-002 · Тёмная тема как единственная

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Обсуждались варианты: только светлая, только тёмная, auto (prefers-color-scheme).

**Решение:** только тёмная тема, без переключателя.

**Причина:**
- Целевая аудитория — технически грамотные люди (разработчики, предприниматели в IT)
- Тёмная тема ассоциируется с профессионализмом в dev-сфере
- Градиенты и акцентный цвет выглядят значительно лучше на тёмном фоне
- Одна тема = вдвое меньше CSS для поддержки

**Последствия:**
- Если маркетинг решит расширить аудиторию — понадобится светлая тема или переключатель
- Все новые компоненты проектируются только под тёмный фон

## ADR-003 · Акцентный цвет — фиолетовый (#c77dff / #7b61ff)

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Рассматривались синий (доверие), зелёный (технологии), фиолетовый (инновации + премиум).

**Решение:** фиолетовый градиент `#c77dff → #7b61ff`.

**Причина:**
- Фиолетовый редко используется в этой нише — выделяет среди конкурентов
- Хорошо сочетается с тёмным фоном, создаёт ощущение "глубины"
- Ассоциации: инновации, технологии, премиум-сегмент

**Последствия:**
- Смена цвета — только через CSS-переменные `--accent`, `--accent-2`, `--accent-glow` в `:root`
- Не хардкодить цвет нигде за пределами `:root`

## ADR-004 · Inline SVG вместо icon-библиотек

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Варианты: Font Awesome, Heroicons CDN, Lucide, inline SVG.

**Решение:** inline SVG прямо в HTML.

**Причина:**
- Нет внешних запросов = нет задержки загрузки
- Иконки стилизуются через CSS (`stroke`, `color`) без лишней специфичности
- Используется ~15 иконок — нет смысла грузить целую библиотеку

**Последствия:**
- При добавлении >30 иконок стоит рассмотреть SVG-спрайт или Iconify

## ADR-005 · Форма без бэкенда в v1.0

- **Дата:** 2026-05-10
- **Статус:** принято (временно)

**Контекст:**
Нужна форма обратной связи. Варианты: собственный API, Formspree, Telegram Bot, EmailJS.

**Решение:** форма показывает success-state без реальной отправки.

**Причина:**
- v1.0 — это MVP для демонстрации дизайна
- Выбор сервиса отправки зависит от инфраструктуры клиента (не определено)
- Шаблоны подключения задокументированы в `CLAUDE.md`

**Последствия:**
- До публикации **обязательно** подключить реальную отправку
- Рекомендуется: Telegram Bot (быстро, бесплатно) или Formspree (надёжно, есть спам-фильтр)

## ADR-006 · CSS без методологий (не BEM, не CSS Modules)

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Варианты: BEM, Tailwind, CSS Modules, просто классы.

**Решение:** плоские классы с семантическими именами (`.card`, `.hero-title`, `.btn-primary`).

**Причина:**
- Проект — один файл, одна страница. BEM избыточен.
- Tailwind требует сборщика (противоречит ADR-001)
- Специфичность намеренно плоская — без `!important`, без вложенных селекторов глубже 2 уровней

**Последствия:**
- При росте CSS > 1000 строк стоит разделить на файлы или перейти на методологию
- Не добавлять `!important` — если нужно перебить стиль, проверь специфичность

## ADR-007 · GitHub Actions для автодеплоя

- **Дата:** 2026-05-10
- **Статус:** принято

**Контекст:**
Нужен автодеплой статики. Варианты: Vercel, Netlify, GitHub Pages вручную, GitHub Actions + Pages.

**Решение:** GitHub Actions workflow (`deploy.yml`) → GitHub Pages.

**Причина:**
- Проект уже в GitHub — нет смысла добавлять сторонний сервис
- GitHub Pages бесплатен для публичных репозиториев
- Actions + официальные `actions/deploy-pages` — нативная интеграция без внешних токенов
- `workflow_dispatch` позволяет запустить деплой вручную из UI

**Последствия:**
- Деплой только из ветки `main` — фича-ветки не публикуются автоматически
- Если проект станет платным/закрытым — GitHub Pages потребует платный план
- При добавлении сборки (минификация, оптимизация) — расширять тот же `deploy.yml`, не создавать новый
